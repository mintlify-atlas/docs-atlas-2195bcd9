---
title: "Quickstart: run the API and submit your first claim"
description: "Stand up the Claims Management System locally, configure your database, start the server, and submit your first claim via the REST API in four steps."
---

This guide walks you through cloning the repository, connecting it to a MySQL database, starting the Spring Boot server, and making two real API calls: one to authenticate and receive a JWT token, and one to register a claim.

<Note>
  **Prerequisites:** Java 17 or later, Maven 3.6+ or the included `mvnw` wrapper (no separate Maven installation required), and a running MySQL database.
</Note>

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/sansauc/claims-management-system.git
    cd claims-management-system
    ```
  </Step>

  <Step title="Configure the environment">
    Create a `.env` file at the project root (the same level as `pom.xml`) and set your database credentials:

    ```bash .env
    DB_URL_DATABASE=jdbc:mysql://localhost:3306/claims_db
    DB_USER=your_db_user
    DB_PASSWORD=your_db_password
    ```

    The included `src/main/resources/application.properties` reads these variables automatically on startup:

    ```properties application.properties
    spring.datasource.url=${DB_URL_DATABASE}
    spring.datasource.username=${DB_USER}
    spring.datasource.password=${DB_PASSWORD}
    ```

    Spring Boot 2.4 and later loads `.env` files from the project root automatically. If you are running an older version, use the `dotenv-maven-plugin` or export the variables in your shell before running the server.
  </Step>

  <Step title="Start the server">
    <CodeGroup>

    ```bash Unix (Linux / macOS)
    ./mvnw spring-boot:run
    ```

    ```bash Windows
    mvnw.cmd spring-boot:run
    ```

    </CodeGroup>

    The server starts on port `8080`. On first run, `DataInitializer` seeds the database with the required roles, claim statuses, and sample data.

    <Tip>
      Swagger UI is available at [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html) once the server is running. You can browse and try every endpoint there without writing any code — no authentication required to view the docs.
    </Tip>
  </Step>

  <Step title="Make your first API call">
    **Step 4a — Authenticate and get a token**

    Post your credentials to `/login`. The server validates them and returns a JWT token in both the response body and the `Authorization` response header.

    ```bash
    curl -X POST http://localhost:8080/login \
      -H "Content-Type: application/json" \
      -d '{"username": "your_username", "password": "your_password"}'
    ```

    Response:

    ```json
    {
      "token": "eyJ...",
      "username": "your_username",
      "message": "Bienvenido your_username, has iniciado sesión de manera exitosa."
    }
    ```

    Copy the value of `token` for the next call.

    **Step 4b — Register a claim**

    Use the token as a `Bearer` credential. This endpoint requires `ROLE_SALE_EMPLOYEE`.

    ```bash
    curl -X POST http://localhost:8080/api/claims \
      -H "Authorization: Bearer eyJ..." \
      -H "Content-Type: application/json" \
      -d '{
        "clientId": 1,
        "contractId": 1,
        "claimTypeId": 1,
        "classification": "URGENT",
        "description": "No internet service"
      }'
    ```

    The system creates the claim with status `Alta`, then immediately runs the assignment engine and updates the claim to `Asignado`. The response includes the full claim object with both history entries.
  </Step>
</Steps>
