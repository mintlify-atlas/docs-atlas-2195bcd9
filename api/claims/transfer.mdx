---
title: "POST /api/claims/claim-transfer — hand off a claim"
description: "Transfer an assigned claim to another Technical Employee. The system re-runs the assignment engine (excluding the caller) and creates a Transfer audit record."
---

Use this endpoint to hand off a claim to a different Technical Employee when the current assignee cannot resolve it. The system re-runs the assignment engine (excluding the requesting technician) and creates both a `Transfer` record and a `ClaimHistory` entry.

**`POST /api/claims/claim-transfer`** — requires `TECHNICAL_EMPLOYEE` role.

<ParamField body="idClaim" type="long" required>
  The ID of the claim to transfer. Must be in the authenticated technician's assigned (pending) list.
</ParamField>

<ParamField body="motivation" type="string" required>
  Reason for the transfer (recorded in the Transfer audit record).
</ParamField>

```bash
curl -X POST http://localhost:8080/api/claims/claim-transfer \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "idClaim": 5,
    "motivation": "Requires fiber optic specialist"
  }'
```

## Response

Returns HTTP 200 with the updated claim. The `currentStatus` is set to `"Transferido"`. The claim is added to the new technician's assigned list, but the status field remains `"Transferido"` — reflecting that a handoff occurred.

## Error responses

| Status | Meaning |
|--------|---------|
| 500 | Claim is not in the authenticated technician's assigned list |
| 404 | Claim not found |
